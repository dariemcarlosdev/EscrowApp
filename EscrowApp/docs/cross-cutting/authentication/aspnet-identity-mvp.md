# ASP.NET Core Identity — MVP Implementation

> Track B: User authentication for the EscrowApp MVP.
> 
> Status: **Planned for #3** — Unblocks user dashboard and transaction creation

## Overview

The EscrowApp MVP uses **ASP.NET Core Identity** for user authentication. This provides email/password registration and login with built-in password hashing, email confirmation, and claims-based identity — sufficient for MVP.

> **Post-MVP Upgrade Path:** Migrate to Entra ID for enterprise authentication with MFA, SAML, and organizational SSO. Identity can coexist with Entra ID via claims enrichment.

## Design Decisions

| Question | Decision | Rationale |
|----------|----------|-----------|
| Identity database | Shared `EscrowDbContext` | Simpler for MVP — no separate Identity DB. Post-MVP: migrate to Duende IdentityServer |
| Login flow | Form-based (traditional) | Blazor Server supports redirects to login page naturally |
| Password reset | Email-based (stub) | Stripe doesn't need password reset in MVP; UI placeholder for future |
| MFA | Not implemented (MVP) | Post-MVP feature — revenue gate: "MFA when 10+ users" |
| Email verification | Optional (allow unverified) | Users can transact before email confirmation — stricter post-MVP |

## Database Schema

### ApplicationUser

Extends `IdentityUser<int>` to preserve integration with `Actor` and `IdentityMapping`:

```csharp
public class ApplicationUser : IdentityUser<int>
{
    // From IdentityUser<int>:
    // Id, UserName, NormalizedUserName, Email, NormalizedEmail
    // PasswordHash, SecurityStamp, ConcurrencyStamp
    // PhoneNumber, PhoneNumberConfirmed, TwoFactorEnabled, LockoutEnd, LockoutEnabled, AccessFailedCount
    
    // Custom properties:
    public int? ActorId { get; set; }              // FK → Actor (for hybrid identity bridge)
    public Actor? Actor { get; set; }              // Navigation property
}
```

**Design note:** `ActorId` is optional to support the Web2 → Web3 bridge (user can register without an Actor, then link to Actor later when onboarding for payments).

### Database Tables (Auto-generated by Identity)

Identity scaffolding creates these tables:

| Table | Purpose |
|-------|---------|
| `AspNetUsers` | ApplicationUser records |
| `AspNetRoles` | Authorization roles (e.g., "Admin", "Consultant", "Client") |
| `AspNetUserRoles` | Join table: which users have which roles |
| `AspNetUserClaims` | Custom claims per user |
| `AspNetUserLogins` | External login providers (future: Google, GitHub) |

**Indexes:** Unique on `NormalizedUserName` and `NormalizedEmail` (case-insensitive)

### Phase 3b: DI Registration (Program.cs)

```csharp
// Add Identity services
builder.Services
    .AddIdentity<ApplicationUser, IdentityRole<int>>(options => {
        options.Password.RequiredLength = 8;
        options.Password.RequireDigit = false;           // MVP: lenient
        options.Password.RequireUppercase = false;       // Allow "password123"
        options.User.RequireUniqueEmail = true;
        options.SignIn.RequireConfirmedEmail = false;    // MVP: optional confirmation
    })
    .AddEntityFrameworkStores<EscrowDbContext>()
    .AddDefaultTokenProviders();

// Add Authentication + Cookie scheme
builder.Services.AddAuthentication(IdentityConstants.ApplicationScheme)
    .AddIdentityCookies();

// Add Authorization policies
builder.Services.AddAuthorization(options => {
    options.AddPolicy("ApiAccess", policy =>
        policy.RequireAuthenticatedUser()
              .RequireClaim("api_scope", "escrow:read", "escrow:write"));
});
```

**Pattern:**
```csharp
// Login.razor.cs
public sealed partial class Login
{
    [Inject] private SignInManager<ApplicationUser> SignInManager { get; set; } = default!;
    [Inject] private NavigationManager Navigation { get; set; } = default!;
    [Inject] private IStringLocalizer<SharedResource> L { get; set; } = default!;

    private string _email = "";
    private string _password = "";
    private string? _errorMessage;

    public async Task OnSubmitAsync()
    {
        var result = await SignInManager.PasswordSignInAsync(_email, _password, isPersistent: true, lockoutOnFailure: false);
        
        if (result.Succeeded)
            Navigation.NavigateTo("/dashboard");
        else
            _errorMessage = L["LoginFailed"];
    }
}
```

### Phase 3e: Actor Linkage

When a user registers, optionally create an `Actor` record:

```csharp
// In RegisterAsync
var user = new ApplicationUser { UserName = email, Email = email };
var result = await UserManager.CreateAsync(user, password);

if (result.Succeeded)
{
    // Create Actor if this is a payee (consultant)
    var actor = new Actor { DisplayName = email, WalletAddress = null };
    await _repository.AddActorAsync(actor);
    
    // Link user to actor
    user.ActorId = actor.Id;
    await UserManager.UpdateAsync(user);
}
```

## Security Guardrails — MANDATORY

| Rule | Implementation | Why |
|---|---|---|
| **No plaintext passwords** | ASP.NET Identity hashes with bcrypt by default | Unrecoverable if database is breached |
| **Timing-safe comparison** | `SignInManager` uses `IPasswordHasher<T>` | Prevents timing attacks on password comparison |
| **CSRF protection** | Blazor Server + antiforgery middleware | POST requests must include CSRF token |
| **Secure cookies** | `HttpOnly`, `Secure`, `SameSite=Strict` (configured by IdentityConstants) | Prevents XSS/CSRF cookie theft |
| **Email case-insensitive** | `NormalizedEmail` index, UserManager.FindByEmailAsync() | Prevents duplicate accounts (user@example.com == USER@EXAMPLE.COM) |
| **Password requirements** | Configurable in AddIdentity() options | MVP: lenient (8 chars), Post-MVP: strict |
| **Account lockout** | `LockoutEnabled = true`, `LockoutDuration = 5 min` | Brute-force protection |

[Fact]
public async Task LoginPage_ValidCredentials_RedirectsToDashboard()
{

## Post-MVP Enhancements

| Feature | Trigger | Why Deferred |
|---------|---------|--------------|
| Email confirmation | "Users report receiving unverified accounts" | Non-blocking for MVP; can enable later |
| Password reset | "Users request password reset flow" | Complexity without email service setup |
