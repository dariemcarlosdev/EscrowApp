## Bridge Architecture

**Unified Skills Ecosystem:**
- `.github/skills/` = Universal skill source (56 skills, flat structure)
- `.claude/skills/` = Claude Code bridge layer (minimal, redirects to `.github/skills/`)
- All other platforms read directly from `.github/skills/` or their own bridge layers

**Bridge file format** (example for `owasp-audit`):
```markdown
# owasp-audit

> Claude Code bridge — read the universal skill for full instructions.

**Read:** `.github/skills/owasp-audit/SKILL.md`

Follow the Core Workflow steps inside. Load `references/*.md` on-demand as each step requires them.
```

## Platform Integration

| Platform | Source | Access Method |
|----------|--------|---|
| **Copilot CLI** | `.github/skills/` (flat) | Direct: `copilot "Use {skill-name}..."` |
| **Claude** | `.claude/skills/` bridges → `.github/skills/` | `/skill-name` in Claude Code |
| **Gemini** | `.github/skills/` (flat) | Prompt context or direct reference |
| **Codex** | `.github/skills/` (flat) | Direct reference or prompt injection |

## Using Skills

### Copilot CLI
```bash
# Skills in .github/skills/ are automatically discovered
copilot "Use the agent-orchestrator skill to coordinate analysis"
copilot "Use the owasp-audit skill to review security"
```

### Claude Code
```
Type: /skill-name
Example: /owasp-audit, /code-reviewer, /agent-orchestrator
```

### Gemini / Other LLMs
```
Reference the skill directly:
"Follow .github/skills/owasp-audit/SKILL.md to review this code for OWASP Top 10..."
```

## Conventions

- All 56 skills live in `.github/skills/` at the root level (flat)
- Each skill has a `SKILL.md` file with Core Workflow + optional `references/` subfolder
- Reference files are lazy-loaded — load only when the workflow step requires it
- Claude bridges in `.claude/skills/` are minimal (< 20 lines each) — they redirect to `.github/skills/`
- All skills are self-contained but declare related skills for cross-referencing
- Skills work identically across all platforms (Copilot, Claude, Gemini, Codex)
